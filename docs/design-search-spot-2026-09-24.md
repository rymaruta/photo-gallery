# Journey Photo「さがす」＋「撮影地ガイド」UI試作（2026-09-24）

このブランチは **PR #143（`claude/spot-guide`）の上に重ねたデザイン確認用**。develop/main には未反映。公式スポットの型・公開基準・保存APIは変更しない。

## 何を変えたか

### /search（写真をさがす）

- サーバー側で **公開可能な公式スポットを最大3件だけ**抽出し、軽量なカード情報だけを検索画面へ渡す。全台帳をクライアントへimportしない。
- 写真検索の既存フィルターより前に、写真付き（確認済みの運営素材がある場合だけ）の「景色から、旅先を見つける」を表示。横スクロール（スマホ）／3列（PC）。
- **公開可能な公式スポット0件なら導線全体を描かない。** 写真検索だけが従来どおり使える。投稿写真0件でも、公式スポットがあれば入口が出る。
- サーバー側では第三者のクレジット必須画像をこの小さなカードへ配信しない。ガイド詳細で適切なクレジットとともに表示する。
- 既存の検索URL・色検索・カテゴリ・タグ・写真モーダルは変更しない。

### /spots（公式撮影スポット索引）

- 公式台帳の正式名、読み、別名、地域、カテゴリから**実際の公開スポットだけを文字検索**する。
- ユーザー写真の検索結果とは独立し、テーマの候補も登録済みカテゴリからだけ生成。スマホ2列／PC3列の写真グリッド、写真なしは固有名のタイポグラフィで表示。
- 検索に該当しない状態と、公開スポット0件の状態を区別。架空の「人気」・投稿数・代表写真を追加しない。

### /spots/[slug]（撮影地ガイド）

- 一覧へ戻れるパンくず、控えめなブランド見出し、**実在するセクションだけを指すページ内目次**を追加。
- 見どころと季節の項目は読み飛ばしやすい小カードに再配置。写真0件の節と、根拠がないアクセス項目の既存の非表示規則を維持。
- 画面幅・公開条件・公式画像の権利判定・地図・行きたい場所の保存経路は変更しない。

## レビュー時の確認画面

1. **390×844、430×932、768×1024、1280×800、1536×864**で検索→公式ガイド→写真検索の往復を確認する。
2. 公開スポット0件（現在の `content/spots.json = []`）、3件ある状態、カテゴリ1種と複数種、代表写真あり／なし、ユーザー写真0件の状態を別々に確認する。**公開用JSONに架空データを書かない**。一時的なfixtureやローカルテストデータを使った場合は公開ビルドへ混ぜない。
3. スマホでは検索導線が高くなりすぎず、タブ・フィルター・写真が押せるかを確認する。PCでは3列の公式カードと写真検索の左フィルターが独立して収まるかを確認する。
4. キーボード、長い日本語・英語名、折り返し、狭い画面、コントラスト、フォーカス、画像なし、画像失敗、戻る／進む、`/search?category=`・`?photo=`直開きを確認する。
5. 新規カードの画像サイズ・Lazy Loading・実転送量を検査する。現行の公式 `coverImage` は派生サイズを持たないため、カード用画像の配信が重い場合は専用の合法な小サイズ画像が出来るまでカードで画像を出さない判断も可能。

**必須の未実施関門**: 作業ブランチを実行できる環境で `npm run verify`（型・lint・Vitest・本番に近いビルド・Chromium実表示）を通す。今回のGitHub経由のコード更新だけで緑とは言わない。PR #143自体の統合テストとコンフリクトの確認も必要。
