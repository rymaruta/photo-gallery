# 「この写真を見て撮影」（`inspiredBy`）— 2026-10-14

owner のめざす姿「**写真から、次の旅が始まるSNS**」の最初の一歩。
人の写真を見て、その場所へ行って撮った人が、投稿するときに
「この写真を見て来ました」と**元の写真**を付けられる。

実装: `api-user/src/inspired.ts`（判定・通知・読む口）／`upload.ts`・`photoUpdate.ts`（書く口）／
`lib/utils/inspired.ts`・`app/components/InspiredByLine.tsx`（Web の写真ページ）

---

## 1. 守っている線（承認制）

| | |
|---|---|
| 新しい表・新しい GSI | **作っていない**。写真の行に欄が2つ足され、同じ表に印の文書（`inspiredNotif#<写真の id>`）が1枚につき1つ増えるだけ |
| 本番のデータ | **既存の写真の行は触らない**。新しく投稿する・編集する写真にだけ書く |
| 「元の写真に、ここから生まれた写真を並べる」 | **作らない**（逆引きは GSI か全表 Scan が要る） |
| 費用 | 読み取りが増えるのは「元の写真が付いた写真」を開いたときだけ（下の 4） |

## 2. データの形（写真の行）

| 欄 | 中身 | 外に出すか |
|---|---|---|
| `inspiredBy` | 元の写真の ID（文字列・英数とハイフン 1〜64文字） | **出す**（一覧・`photos.json` にも ID だけ載る） |
| `inspiredNotified` | 通知を決めた**控え**（`sent` / `skipped`）。編集のたびに印の文書を引かないための目印 | **出さない**（`PRIVATE_FIELDS` の4つの写し。`privateFieldsParity.test.ts` が縛る） |

同じ表の別のキーに**印の文書**（正）を置く:

| キー | 中身 |
|---|---|
| `inspiredNotif#<写真の id>` | `{ photoId, sourceId, status: "sent" \| "skipped", t }`。**無いときだけ書く**（`attribute_not_exists(id)`）。`src` を持たないので写真の一覧には出ない |

写真の行の控えだけだと、再送の書き直し（`overwriteOwnPhoto` の全置換）と重なったときに控えが消え、
**通知が2回届く窓**があった（レビューで指摘）。正を別の文書に移したので、控えが消えても二重には送らない。
**古い版の印**（写真の行の `inspiredNotified` に元の写真の ID）がある行は「決め済み」として扱う。

**`inspiredBy` は ID だけ。** 元の写真の中身（題・画像・作者）は、出す側が
「今も見られるか」を確かめてから解く（下の 4）。ID は不透明な uuid で、
見られない写真の ID からは何も読めない（`GET /photos/{id}` も 404）。

## 3. 書くときの決まり

### 元の写真として付けられるもの（`readVisibleSource`）

- **実在し、公開で見られる**写真だけ。判定は公開一覧と同じ `feed.ts` の `isPublicListPhoto`
  （下書き・ストーリー・公開範囲を絞った写真・`src` の無い行は×）
- **元の作者と付ける人が、どちら向きにもブロックの関係に無い**こと（`blockCheck.ts` の `isBlocked`。印を引く）
- **この写真自身は×**
- **自分の写真は○**（再訪の記録。通知は送らない）
- 値の形: 英数とハイフンだけ・1〜64文字。`#` を含む値（`notifs#…` などの文書のキー）は形の段階で×

### 投稿（`POST /upload/save`）

- 形の違う値 → **400**「元の写真の指定が正しくありません」（`null`・`""`・省略は「付けない」）
- 形は合うが**見られない元の写真 → 黙って付けない**（投稿は成功。画像はもう S3 に上がっているので止めない）。
  付いたかは応答の `photo.inspiredBy` で分かる
- 確かめる読み取りが失敗したときも付けない（投稿は止めない）

### 編集（`PUT /photos/{id}`）

- `inspiredBy: null` または `""` → **外す**（REMOVE。確かめない）
- 形の違う値 → **400**「元の写真の指定が正しくありません」（付けてあったものを黙って消さない）
- 新しい値で、見られない元の写真 → **400**「元の写真が見つからないか、付けられません」
  （理由は言い分けない——見られない写真の在りかを教えない）
- **保存済みと同じ値なら確かめ直さない**（元の写真があとで非公開になっても、関係の無い保存まで断らない。読む側で毎回確かめている）
- 付ける・外すは静的ページの作り直しを頼む（写真ページに行が焼かれるので。他の項目と同じ `coalesce`）

## 4. 読むときの決まり（読むときにも確かめる）

付けたときは公開でも、あとで非公開・削除・ブロックになりうる。

### Web（写真ページ）— 読み取りの増加 **0**

- **静的な `photos.json` を作るとき（sync）に落とす**（`scripts/sync-photos-from-ddb.js` の `pruneInspiredBy`）:
  - 元の写真が公開の一覧に居ない（非公開・下書き・削除・絞った写真）——見られない写真の ID を全員に配る JSON に残さない
  - **付けた人と元の作者のあいだに、どちら向きでもブロックの印**（同じ表の `block#<した人>#<された人>`）がある
    ——ブロックしたのに、相手の写真ページから自分の写真へのリンクが残り続ける（付きまといの道）のを塞ぐ
  - 読み取りは増やさない（全表の Scan で既に手にしている写真とブロックの印だけで決める）
- 写真ページは**ビルド時に解いたものだけ**を出す（静的HTMLにも焼く。写真から写真への内部リンク）。
  クライアントで取得した `GET /photos` は**減らす側にだけ**使う——一覧で `inspiredBy` が外れた・元の写真が
  居なくなったら消す。`GET /photos` はブロックを見られないので、**API の一覧だけで行を出す（復活させる）ことはしない**
- `GET /photos`（管理API・未認証）も、返す一覧に元の写真が居るときだけ `inspiredBy` を残す（`?userId=` では載せない）
- ⚠️ ブロックを外したあとにつながりが戻るのは**次のビルドから**（ブロックしたときも同じ。ブロックは再ビルドを頼まないので、
  落ちるのは次のビルド（写真の投稿・編集・削除などで起きる）から）
- ⚠️ **閲覧者本人**とのブロックは見ない（静的なページには閲覧者が居ない。Web の他の公開ページと同じ）。
  閲覧者まで見るのはアプリ向けの口（下）
- Web では**付ける入口は作っていない**（アプリが先）。編集画面（`/user/edit`）で**外す**ことだけできる

### アプリ — `GET /user/inspired/{id}`（認証必要）

写真 `{id}` に付いている元の写真の要約を返す。閲覧者 ↔ 元の作者、付けた人 ↔ 元の作者の
**両方を、どちら向きにも**見る。

読み取り（**1回の表示あたり**・すべて GetItem）:

| | 回数 |
|---|---|
| 写真 `{id}` | 1 |
| 元の写真 | 1 |
| ブロックの印（閲覧者↔元の作者・付けた人↔元の作者、各2向き） | 4（閲覧者が付けた本人なら 2） |
| 元の作者のいまの名前（users テーブル） | 1 |
| **計** | **最大 7**（付けた写真が公開範囲を絞った写真なら `canViewPhoto` の最大3が足される） |

| ブロックの印の内訳 | 閲覧者・付けた人のうち元の作者でない人ごとに2（閲覧者＝付けた人、または一方が元の作者なら 2） |

一覧の口（`GET /feed`・`/feed/restricted`・`/user/photos`）は `inspiredBy`（ID）を**素通しで返すだけ**
（読み取りは増えない）。`GET /photos` は一覧に元の写真が居るときだけ残す（増えない）。
アプリは **ID を持つ写真の詳細を開いたときだけ**この口を呼ぶ。

### 書くとき・通知のときの読み取り（実数）

| 場面 | 読み取り（GetItem） | 書き込み |
|---|---|---|
| 投稿で付けた（公開） | 元の写真1 ＋ ブロックの印2（自分の写真なら0）。**通知の判定はこの行を使い回す**（読み直さない）。印の文書を1回（決め済みか）。通知するなら付けた人の名前1 ＋ `pushNotification` の中の分 | 印の文書1・行の控え1・通知1 |
| 編集で新しく付けた（公開） | 同上（確かめで読んだ行を通知に渡す） | 同上 |
| 下書きで付けてあった写真を公開した | 印の文書1 ＋ 元の写真1 ＋ ブロックの印2（自分の写真なら0）。通知するなら名前1 ＋ `pushNotification` の分 | 同上 |
| 印のついた写真の編集（以後ずっと） | **0**（行の控え `inspiredNotified` を見て何も読まない。送らないと決めた自分の写真も同じ） | 0 |
| 控えが再送の書き直しで消えていた | **印の文書1だけ**（決め済みと分かったら元の写真は読まない） | 行の控えの書き戻し1（以後は 0 に戻る） |

## 5. 通知（`inspired`）

| | |
|---|---|
| 種類 | `inspired`（`notify.ts` の `Notif`。Web の `NotificationsBell` にも足した） |
| 宛先 | 元の写真の作者 |
| `photoId` / `photoSrc` | **付けた人の新しい写真**（押すとそこへ） |
| `sourcePhotoId` | 元になった（受け取った人の）写真 |
| `byName` / `byId` | 付けた人（名前はサーバーで引く） |
| いつ | 付けた写真が**公開で見られる状態になったとき**（公開で投稿・編集で付けた・下書きから公開・再送で公開） |
| 送らない | 自分の写真／どちら向きでもブロック／元の写真が見られない／付けた写真が下書き・公開範囲を絞った写真 |
| 二度と送らない | **1枚の写真につき1回だけ**。印の文書 `inspiredNotif#<写真の id>` を条件つき（`attribute_not_exists`）で書けたときだけ送る。編集・再送（書き直しと重なっても）・付け替え・外して付け直しでは鳴らない。同時に2本来ても1本 |
| 送らないと決めた写真 | 自分の写真・ブロック・元の写真が見られない、と決まったら `skipped` の印を立てる（以後は**読みもしない**）。⚠️ そのため、**あとでブロックを外しても・元の写真を公開に戻しても送らない**。読めなかった（DynamoDB の失敗）ときは印を立てない |
| 設定 | 既存の種類と同じ `pushNotification` を通す（ブロックした相手からは積まない・端末のプッシュ・50件の上限）。サーバー側に種類ごとのオフ／ミュートの設定は無い（端末のプッシュの許可が効く） |
| プッシュ | 鍵 `NOTIF_INSPIRED`（引数は付けた人の名前）。data は `type`・`photoId`・`byId`・`sourcePhotoId` |
| Web の文言 | 「○○ さんがあなたの写真を見て撮影しました」／「○○ took a photo inspired by yours」。タブは「すべて」にだけ出る |

⚠️ **付け替えた先の作者には届かない**（「最初に付いたときだけ」を守るため）。

## 6. iOS 向けの API の形（まとめ）

**送る欄**

```jsonc
// POST /upload/save（3段目）に足す
{ "inspiredBy": "aaaaaaaa-1111-4111-8111-111111111111" }   // 元の写真の id。省略・null・"" で付けない

// PUT /photos/{id}
{ "inspiredBy": "<元の写真の id>" }   // 付ける・付け替える（見られない写真は 400）
{ "inspiredBy": null }                // 外す
```

- 400 の文言: 「元の写真の指定が正しくありません」（形）／「元の写真が見つからないか、付けられません」（編集で見られない写真）
- 投稿で見られない写真を指したときは 400 にならない——応答の `photo.inspiredBy` が無いことで分かる

**返る欄**

- 写真の行（`GET /feed`・`/feed/restricted`・`/user/photos`）: `inspiredBy?: string`（**ID だけ・今も見られるかは未確認**）。
  `photos.json` と `GET /photos` は元の写真が公開の一覧に居るときだけ残す（`photos.json` はブロックの関係でも落とす）
- `GET /user/inspired/{id}`（認証必要・`Cache-Control: private, no-store`）:

```jsonc
200 { "inspiredBy": {
        "id": "…", "title": "…" | { "ja": "…", "en": "…" }, "src": "…",
        "thumbSrc": "…",            // 任意（256px → 512px の順で、あるもの）
        "location": "…",            // 任意
        "userId": "…", "displayName": "…", "username": "…"   // 名前・@名は任意（いまの名前）
} }
200 { "inspiredBy": null }   // 付いていない／元の写真がもう見られない（非公開・削除・ブロック）
404                           // 写真 {id} が無い・この人に見せられない（下書き・絞った写真）
500                           // 読めなかった（「無い」とは言い切らない）
```

**通知の種類**

- `GET /user/notifications` の `items[]` に `type: "inspired"`（`photoId`＝付けた人の写真・`sourcePhotoId`＝自分の写真・`byName`・`byId`）
- プッシュ: `loc-key` = `NOTIF_INSPIRED`（`Localizable.strings` に足すこと。足さないと鍵がそのまま出る）、
  data = `{ type: "inspired", photoId, byId, sourcePhotoId }`
