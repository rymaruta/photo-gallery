## 3. 公式撮影地ガイドのデータモデル

**→ `docs/spot-guide-2026-09-23.md` §3。** 要点だけ:

- **#132 の `Spot` 型を土台にする**（独立した `spotId`・改名で変わらない `slug`・
  `region`・`status`・`verified`）。**新しい型を作らない**
- develop の `SpotMasterEntry`（3項目）は `Spot` に**畳む**＝型は1つ
- 足すのは 見どころ／季節／時間帯／構図／アクセス／駐車場／注意点／公式サイト／
  周辺スポット／**代表写真（権利つき）**／**項目ごとの出典と確認日**
- **出典が無い項目は画面に出さない**（表示側で機械的に効かせる）
- **営業時間・料金の項目は作らない**（変わりやすく実害が出る。公式サイトへ送る）

## 4. 既存の `/location/*` との役割の違い

| | `/location/<スラッグ>`（既存・**維持**） | `/spots/<slug>`（新規） |
|---|---|---|
| 何のページか | **地域・撮影地の集約**（写真の一覧） | **個別の撮影地点の公式ガイド** |
| 元になるもの | 利用者が写真に書いた撮影地の文字列 | 運営の台帳（`Spot`） |
| 写真0枚だと | **存在しない**（いまの仕様） | **存在する**（今回の肝） |
| 鍵 | 文字列のスラッグ | `spotId`（名前から作らない） |
| 例 | `/location/パリ`・`/location/山中湖` | `/spots/takaya-jinja` |

**混同しない。** 地域は集約、地点は台帳。片方を消したり一律で振り替えたりしない。
両者は**相互にリンク**する（集約 → その中の公式スポット／スポット → 地域の集約）。

## ✅ もう1つの預かり — 済（2026-09-24・PR #151 / #152 / #153）

owner の報告:「**色タグが仕事してない気がする。写真の色と違うタグが選ばれてる
こともある**」。**本番で数えたら、そのとおりだった。**

まず数える道具を足し（`maintenance` → `photo-colors`・読み取り専用）、
本番で流した:

    公開39枚のうち **21枚（54%）** で、いまのタグと中身が食い違う
    「黒」と出ている16枚のうち、**無彩色しか無いのは1枚だけ**（白鳥と湖）
    `dominantColor` が `#080808` `#181818` のほぼ真っ黒 …… 12枚

      ヴェルサイユ宮殿  黒 #080808 → 実際は 橙 98%
      高千穂峡          黒 #181818 → 実際は 緑 95%
      北海道の桜        黒 #080808 → 実際は 橙 100%

原因は `lib/color/buckets.ts` が自分で書いていたとおり——`dominantColor` は
sharp の `stats().dominant` ＝**いちばん多い1ビン**で、写真ではたいてい影の色。

**直したのは画面側**（`lib/color/useBlurColors.ts`）。`blurDataURL`（20px の
公開ぼかし）から、**無彩色の画素を除いた分布の1位**をその場で決め直す。
**本番データは1件も書き換えていない**——`usePhotos` は API の応答で配列ごと
差し替えるので、ビルド時のファイルに書いても届いた瞬間に消えるため。

重さは実ブラウザで測ってから入れた（39枚 合計 37ms／CPU 4倍遅くして 184ms。
1枚ずつ `await` で回すので主線を塞ぐのは最大 6.7ms ＝1フレーム内）。
